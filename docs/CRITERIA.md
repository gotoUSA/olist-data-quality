0. 이 데이터는 고정(Kaggle 갱신 예정 Never)이다. 검사의 실제 역할 = 진단 보고 + 분석 관문. 실패(관문)는 본 분석에 쓰는 열에만 둔다. 월별 경고·2단계·알려진 목록 같은 운영 감시 기준은 '운영이라면' 설계로 남기고, 이 데이터에서 실제로 돈 것과 문서에서 나눠 적는다. 운영 흉내는 replay 백테스트(날짜순으로 흘려 넣고 그날까지 데이터로만 기준선)로 한다. (11-13 추가) replay 준비 기간 = 2017-01~06(6개월), 검사 구간 = 2017-07~2018-08. 기준선 사건이 0건이면 경고 대신 '기준선 부족'으로 표시(11-15, D34).
1. 날짜 순서 검사는 1시간 미만 차이를 시계 오차로 보고 세지 않는다.
2. 건수형 검사는 2단계: 실패 = 전체 비율 고정 기준, 경고 = 월별 포아송 정확 검정 P < 1%(기준선 = 분석 기간 전체). 기준 숫자는 검사마다 이유를 달아 정한다.
3. 기준의 방향은 놓쳤을 때의 피해로 정한다. 분석에만 영향을 주는 검사는 헛경고를 피하는 쪽(검사 수 × 기간이 커서 헛경고가 쌓임), 돈·운영에 영향을 주는 검사(결제, 승인)는 놓침을 피하는 쪽. (11-13 수정: 처음엔 모든 검사에 '헛경고 피함'을 적용했음)
4. 처리 기본값 = 행을 지우지 않고 그대로 둔다. 분석에 쓰는 열이 영향을 받을 때만 따로 정한다.
5. 기준을 데이터를 보고 정했으면 그 한계(같은 데이터로 확인함)를 적는다.
