# 개념 정리

검증 기준을 정하면서 쓴 통계·데이터 품질 개념. 결정과 이유는 `CRITERIA.md`에 있다.

## IQR (사분위 범위)와 이상치 기준
1. 값을 작은 것부터 정렬한다.
2. 25% 지점 = Q1, 75% 지점 = Q3. 배송 기간 기준 Q1 6.8일, Q3 15.7일.
3. IQR = Q3 − Q1 = 8.9일. 가운데 절반의 데이터가 퍼진 폭이다.
4. 상한 = Q3 + 1.5 × IQR = 29.1일, 하한 = Q1 − 1.5 × IQR. 상한·하한을 벗어나면 이상치로 본다.
5. 1.5는 관례다. 정규분포라면 약 0.7%가 이상치로 잡힌다.

평균·표준편차(z-score) 대신 쓰는 이유: Q1·Q3는 정렬한 위치라서 맨 끝 값이 200일이든 2,000일이든 바뀌지 않는다. 평균과 표준편차는 극단값에 끌려간다.

## 로그 변환 뒤 IQR
IQR 기준은 Q1·Q3에서 같은 거리만큼 떨어진 곳을 상한·하한으로 잡으므로 대칭 분포를 가정한다. 배송 기간은 오른쪽으로 치우친 분포(왜도 3.85)라 그대로 쓰면 상한이 29.1일로 가까워져 4,916건이 잡힌다. 로그를 씌우면 큰 값이 더 많이 줄어 분포가 대칭에 가까워진다. 로그 눈금에서 같은 계산을 하고 일수로 되돌리면 상한이 55.5일, 이상치 426건이다.

## 95% 신뢰구간
- 뜻: 같은 방법으로 표본을 뽑아 구간을 만드는 일을 여러 번 반복하면 그중 95%가 참값을 포함한다.
- 틀린 해석: "참값이 이 구간 안에 있을 확률이 95%다." 이미 만든 구간 하나는 참값을 포함하거나 포함하지 않거나 둘 중 하나다.
- 확인(11-13): 리뷰 점수 전체(평균 4.086)를 모집단으로 놓고 200건씩 100번 뽑아 구간을 만들었더니 94번 참값을 포함했다.
- 95%는 관례다. 99%로 올리면 구간이 넓어지고 90%로 낮추면 좁아질 뿐 더 정확해지지 않는다. 구간의 폭(정밀도)은 표본 크기가 정한다.
- 베이즈 통계의 신용구간(credible interval)은 "참값이 구간 안에 있을 확률"로 해석할 수 있지만 전제가 다르다.

## 큰 표본에서 p값
표본이 9만 건이면 아주 작은 차이도 거의 항상 유의하게 나온다. 그래서 p값 대신 효과 크기(평균 차이, 1~2점 비율 차이)와 신뢰구간으로 말한다.

## 포아송 정확 검정
드문 사건(한 달 0~3건)의 건수가 평소 비율에서 나올 확률을 직접 계산한다. 관리도(p-chart)는 정규분포 근사를 쓰는데, 기대 건수가 1건 미만이면 근사가 맞지 않는다.

## 결측의 종류
| 유형 | 뜻 |
|---|---|
| MCAR (완전 무작위 결측) | 빠지는 것이 순전히 우연 |
| MAR (무작위 결측) | 관측된 다른 값(시기 등)과 관련 있음. C6 카테고리 결측은 시기에 따라 2.3%→0.55%로 줄어 MCAR가 아님 |
| MNAR (비무작위 결측) | 빠진 값 자체 때문에 빠짐. 데이터만으로 판단할 수 없음 |

## 민감도 분석
같은 계산을 조건을 바꿔 여러 번 하고 결과의 방향이 같은지 본다. 극단값을 지우지 않고 남겨 둔 대신, 뺀 결과도 함께 보고해 결론이 소수에 기대는지 확인한다.

## 절대 규칙과 통계 규칙
- 절대 규칙: 물리적·논리적으로 있을 수 없는 값(공기보다 가벼운 상품, 번역표에 없는 카테고리). 허용 0.
- 통계 규칙: 있을 수는 있지만 드물어야 하는 값(카테고리 결측, 도착일 누락). 비율 기준.
- 운영에서 절대 규칙을 처음 적용하면 기존 위반이 이미 있으므로, 기존 건은 알려진 목록으로 관리하고 새 위반만 실패로 처리한다.

## 고정 데이터와 운영 데이터
판정 기법(IQR, 포아송, 도메인 규칙, 참조 무결성)은 같다. 다른 것은 질문과 비교 대상, 결과 처리다.

| | 고정 데이터 | 운영 데이터 |
|---|---|---|
| 질문 | 이 데이터로 결론을 내도 되나 | 오늘 들어온 데이터가 평소와 같나 |
| 비교 대상 | 데이터 내부 분포 | 과거 기준선 |
| 결과 처리 | 사람이 정제·해석·민감도 분석 | 자동 경고, 파이프라인 차단 |

replay 백테스트: 고정 데이터를 날짜순으로 흘려 넣고 그날까지의 데이터로만 기준선을 잡아 운영을 흉내 낸다. Olist에는 기록이 DB에 들어간 시각이 없어 근사치다.

## 회사에서 기준을 정하는 순서(일반적인 방식)
업무 목표(SLO)에서 시작 → 데이터를 만드는 팀과 쓰는 팀이 합의(데이터 계약) → 과거 데이터로 기준선 → 장애 기록과 대조 → 알림 없이 기록만 쌓는 그림자 운영 → 단계별 알림 → 주기적 재검토.
